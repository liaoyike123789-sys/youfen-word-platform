# 问题排查日志

> 记录测试与部署过程中真实遇到的环境 / 接口 / 数据库问题，以及排查思路与结论。对应简历中"结合 Linux 服务日志、接口请求及数据库查询结果分析异常"的实践。

## 案例 1：Spring Boot 启动后端口被占用

- **现象**：`mvn spring-boot:run` 启动报错 `Web server failed to start. Port 8080 was already in use.`
- **排查**：
  1. `netstat -ano | findstr :8080`（Windows）/ `ss -lntp | grep 8080`（Linux）找到占用进程 PID；
  2. 确认是之前未关干净的 Java 进程。
- **处理**：`taskkill /PID <pid> /F` 杀掉旧进程；或在 `application.yml` 改成其他端口。
- **沉淀**：每次重启前先 `jps -l` 看 Java 进程，避免多实例残留。

## 案例 2：数据库连接失败（Communications link failure）

- **现象**：切换到 MySQL 后启动报 `com.mysql.cj.jdbc.exceptions.CommunicationsException`。
- **排查**：
  1. `ping` / `telnet <host> 3306` 确认网络与端口；
  2. 检查 `application.yml` 中 url 是否带时区 `serverTimezone=Asia/Shanghai`；
  3. 确认 MySQL 用户是否允许远程登录（`user@'%'`）；
  4. 确认库 `youfen` 已 `CREATE DATABASE`。
- **处理**：补时区参数 + 授权远程登录 + 建库后重启成功。

## 案例 3：H2 初始化 SQL 中文乱码

- **现象**：`data.sql` 执行后，`word.meaning` 中文变成 `???`。
- **排查**：
  1. 确认 `data.sql` 文件本身是 UTF-8；
  2. Spring Boot 默认 `spring.sql.init.encoding=UTF-8`，但 H2 连接 URL 未指定字符集；
- **处理**：url 改为 `jdbc:h2:mem:youfen;MODE=MySQL;DB_CLOSE_DELAY=-1;DB_CLOSE_ON_EXIT=FALSE;characterEncoding=UTF-8`，并在 `application.yml` 显式配 `spring.sql.init.encoding: UTF-8`。

## 案例 4：Fiddler 抓不到小程序请求

- **现象**：微信开发者工具里发请求，Fiddler 无记录。
- **排查**：
  1. Fiddler 默认只代理 HTTP，HTTPS 需要装证书并勾选 `Decrypt HTTPS traffic`；
  2. 微信开发者工具需在 设置 → 代理 中显式指定 HTTP 代理为 `127.0.0.1:8888`；
- **处理**：装证书 + 配置代理后可正常抓包，用它对比了 `/api/learning/review` 的请求体与响应。

## 案例 5：接口返回 200 但前端拿到 undefined

- **现象**：小程序端登录接口 Postman 正常，前端拿不到 token。
- **排查**：
  1. Fiddler 对比发现前端读取路径写成了 `res.data.token`，而实际结构是 `res.data.data.token`（外层 code/message/data 是统一包装）；
- **处理**：前端拦截器统一拆包，业务层直接拿 `data`。

## 案例 6：Linux 部署后接口 404

- **现象**：jar 包启动成功，但访问 `/api/health` 返回 404。
- **排查**：
  1. `journalctl -u youfen -f` 或 `nohup` 日志看启动 banner 是否打印；
  2. 确认 `java -jar` 启动的 jar 是不是最新打的（`ll -h` 看时间戳）；
  3. `curl -v http://127.0.0.1:8080/api/health` 直接在服务器本机测，排除 Nginx 转发问题；
- **处理**：实际是打了旧 jar，重新 `mvn clean package` 后上传重启恢复。

## 案例 7：AI 工具辅助排查

- **场景**：遇到不熟悉的异常栈（如 `LazyInitializationException`）时：
  1. 把异常栈粘给 Cursor / Codex，让它解释可能原因；
  2. 让它给出 2~3 种修复方式（`@Transactional`、`JOIN FETCH`、`open-in-view`）；
  3. 结合代码上下文选最小改动方案，并在本地用 Postman 复测验证。
- **结论**：AI 适合快速定位方向和生成排查命令，但**最终结论必须靠日志 + 实际请求验证**，不能直接采纳它改代码。

## 案例 8：禅道用例与实际接口字段不一致

- **现象**：用例写的字段是 `userName`，实际接口是 `username`。
- **处理**：以 Swagger `/v3/api-docs` 为单一事实来源，把 86 条用例与 Swagger 字段对齐一次，避免后续自动化脚本因字段名反复失败。
