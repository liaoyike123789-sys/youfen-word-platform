## BUG-001 详情

- **标题**：用户名重复注册时返回 500 而非业务错误
- **复现步骤**：
  1. POST `/api/auth/register`，body: `{"username":"duplicate","password":"123456"}`，第一次成功；
  2. 再次提交相同 username。
- **预期**：code=400，message="用户名已存在"。
- **实际**：HTTP 500，控制台打印 `DataIntegrityViolationException`（唯一索引冲突）。
- **原因**：开发直接依赖数据库唯一索引报错，未在 service 层提前 `existsByUsername` 判断。
- **修复**：`AuthService.register` 增加 `existsByUsername` 预检。
- **回归**：用例 TC-AUTH-003 通过。

## BUG-002 详情

- **复现步骤**：不带 `Authorization` 头 GET `/api/auth/me`。
- **预期**：code=401，提示未登录。
- **实际**：NPE，HTTP 500。
- **原因**：`authService.currentUser` 直接 `tokenStore.get(null)`，未对 null 做分支。
- **修复**：入参判空，null 直接抛 `BusinessException(401, "未登录")`。
- **回归**：TC-AUTH-010、TC-AUTH-011 通过。

## BUG-006 详情

- **复现步骤**：新用户直接 GET `/api/stats/today`。
- **预期**：learned=0，accuracy=0。
- **实际**：`ArithmeticException / by zero`，HTTP 500。
- **原因**：`known * 100.0 / all` 在 all=0 时未保护。
- **修复**：`all == 0 ? 0 : ...`。
- **回归**：TC-STATS-006 通过。

## BUG-012 详情（致命）

- **标题**：用户 A 的学习记录在用户 B 的错题本里出现
- **复现步骤**：
  1. 用户 A 登录，对 wordId=2 标记 unknown；
  2. 用户 B 登录，GET `/api/learning/wrongbook`。
- **预期**：B 的错题本为空。
- **实际**：B 看到了 wordId=2。
- **原因**：初版 `ReviewItemRepository.findByUserId` 漏写 `@Where` 或查询条件，直接 `findAll()`。
- **修复**：`wrongbook` 接口改为 `reviewRepository.findByUserId(userId)`，并加数据隔离用例 TC-LEARN-020。
- **回归**：数据隔离用例通过，后续在 RestAssured 自动化中固化为接口级回归。
